# Supply-Chain and Dependency Security

## Required dependency evidence

Repository CI is intentionally reproducible from committed inputs:

- Node.js 22 is the supported runtime for repository validation;
- npm dependencies are resolved by committed `package-lock.json`;
- required CI installs project dependencies with `npm ci --ignore-scripts`;
- Wrangler is pinned to an exact version in `package.json`;
- the n8n CLI import smoke uses an explicit version rather than `latest`;
- third-party GitHub Actions used by required CI are pinned to immutable commit SHAs.

The package lock was generated by npm on the same Node-22 GitHub runner/toolchain used to validate the branch before admission.

## Update governance

`.github/dependabot.yml` opens bounded weekly update pull requests for:

- npm development dependencies;
- GitHub Actions references.

Dependency updates are normal code changes: review the diff, preserve the architecture/security boundaries, and require the repository validation workflow before merge.

Do not automatically merge dependency updates solely because they are generated by Dependabot.

## Secret and private-data scanning

Defense in depth is split between repository-owned controls and platform controls.

Repository-owned required checks:

- `npm run privacy:check` scans the complete tracked tree;
- common credential/token shapes are rejected;
- personal/private fixture patterns are rejected;
- exported n8n workflows must contain placeholder-only credential/resource identifiers;
- CI diagnostics avoid echoing matched private payloads.

GitHub-hosted secret scanning, push protection, dependency alerts, and similar repository-security features are useful additional controls when available/enabled for the repository account. This project does **not** treat their account-specific enablement state as proven by source control and does not rely on them as the only publication gate.

## Vulnerability handling

A newly disclosed dependency vulnerability is evaluated by exploitability in this project, affected runtime path, private-data impact, and available remediation.

- critical/private-data boundary vulnerabilities may interrupt feature work;
- routine dependency updates remain bounded pull requests;
- `npm audit` is not a required merge gate because registry advisory state changes independently of the reviewed commit and would make historical CI evidence non-reproducible;
- Dependabot/advisory signals should still trigger a targeted review and update when applicable.

Security reports follow [SECURITY.md](../../SECURITY.md). Accidental disclosure follows the [Public Data Incident Response runbook](../runbooks/public-data-incident-response.md).

## CI permissions

Required validation runs with repository contents read-only. Temporary write access used to bootstrap a generated artifact must not remain in the admitted workflow.

Production Cloudflare, Gmail, Sheets, and n8n credentials are not available to public pull-request CI.
